### Phase 1：安全与权限加固（`fc1edbd`）

**目标**：堵住"笛卡尔积放大"与"行级越权"两大企业级数据安全缺口。

#### 变更内容

| # | 改造点 | 文件 |
|---|---|---|
| 1.1 | 笛卡尔积 JOIN 防御：遍历 AST 所有 JOIN 的 ON 等值条件，必须命中授权 relationships 白名单 | `app/services/sql_guard.py` |
| 1.2 | 行级越权静默注入：解析 `user.data_scope`，校验通过后在 AST 注入 WHERE 过滤 | `app/services/row_level_security.py`、`app/services/sql_guard.py` |
| 1.3 | 列级敏感阻断：guard 增加 `sensitive_columns` 参数，执行前 AST 层拦截敏感字段 | `app/services/sql_guard.py` |
| 1.4 | 权限模型扩展：`UserMySQL` 增 `data_scope` 字段（JSON 多维度），lifespan 幂等补列迁移 | `app/models/mysql/user_mysql.py`、`app/core/lifespan.py` |

#### ✨ 亮点

- **三层纵深防御**：召回阶段过滤 → validate_sql 校验 → execute_sql 二次校验，任一环节漏判都有后手
- **笛卡尔积防御（严格模式）**：LLM 编造的 JOIN（`ON 1=1`、未授权关联）一律熔断，防止指标成倍放大
- **行级权限静默注入**：用户无感，SQL 自动加 `WHERE region='华东'`；admin 全量可见不注入
- **防配置错误越权**：行级权限注入时，列必须唯一可定位，否则拒绝执行
- **完全向后兼容**：guard 新增参数均有默认值，既有 MySQL 部署零改动

### Phase 2：NL2SQL 核心能力（`9d180fa`）

**目标**：引入参考项目最大的两个亮点——Few-shot 自愈学习 + Schema Linking 精排。

#### 变更内容

| # | 改造点 | 文件 |
|---|---|---|
| 2.1 | Few-shot 自愈学习闭环：Qdrant feedback 集合存经验对；correct_sql 召回 Top-3 注入；execute_sql 成功后回写 | `app/repositories/qdrant/feedback_qdrant_repository.py`、`app/services/feedback_learning_service.py`、`app/agent/nodes/correct_sql.py` |
| 2.2 | 清理 dead code：删除 3 个全仓库无引用的 `extend_keywords_*.prompt` | `prompts/` |
| 2.3 | Schema Linking 精排：`filter_island_tables` 孤岛过滤 + `score_by_literal_match` 字面提权 | `app/agent/schema_selection.py`、`app/agent/nodes/merge_retrieved_info.py` |

#### ✨ 亮点

- **纠错可进化**：每次修复成功的 SQL 会回写到 Qdrant，下次类似问题直接召回历史修复方案，系统越用越聪明
- **召回宁缺毋滥**：Few-shot 召回 score_threshold=0.7（高于字段召回的 0.6），避免错误经验误导 LLM
- **全链路异常静默降级**：召回/回写失败都不阻断主查询流程，保证服务可用性
- **孤岛过滤防幻觉**：丢弃与主分析链路无连通的维度表，减少 LLM 编造 JOIN 的幻觉面
- **字面提权提升注意力**：query 原文命中的字段/指标自动提到召回结果前面（name+10/alias+5/desc+2）

## 六、技术亮点总结

### 1. 纵深防御的安全架构

SQL Guard 从单层校验升级为**三层纵深防御**：

```
召回阶段过滤（sensitive/island）
    ↓
validate_sql 校验（AST 白名单 + JOIN 防御 + 敏感阻断）
    ↓
execute_sql 二次校验（防篡改）
```

### 2. 自愈学习的闭环设计

```
correct_sql 召回历史经验 → 注入 prompt → LLM 修复 → execute 成功 → 回写经验
                                                              ↑
                                                          越用越准
```

### 3. 全链路优雅降级

| 故障场景 | 降级行为 |
|---|---|
| Redis 不可用 | 透明走直查 |
| 物理库断线 | 返回结构化降级提示，不崩服务 |
| Qdrant 召回失败 | 回退词法检索 |
| Few-shot 召回失败 | 回退零样本纠错 |
| OTel 初始化失败 | 降级为禁用 tracing |

### 4. 多方言可扩展架构

新增数据源只需：继承 `DialectStrategy` + 实现 6 个方法 + 在工厂注册。sql_guard / repository / client manager 全部自动适配。

### 5. 前后端双侧质量门禁

| 门禁 | 后端 | 前端 |
|---|---|---|
| 提交前钩子 | ruff + black + yaml 检查 | eslint + prettier |
| CI 流水线 | ruff + mypy + pytest | eslint + prettier + tsc + build |
| 类型检查 | mypy | tsc --noEmit |

## 七、未完成事项

### Phase 5：DSL 中间层（决策点）

**状态**：暂不实施，作为 Phase 2 Few-shot 验收后的决策点。

**判断逻辑**：
- 先让 Phase 2 的 Few-shot 自愈 + Schema 精排上线运行
- 观察准确率是否达标（建议目标 ≥ 90%）
- 若达标 → DSL 不必做
- 若仍不达标 → 启动 DSL 中间层（NL → QueryDSL → 确定性编译 → SQL）

**预期收益**：编译器确定性消除 LLM 在 SQL 语法层的幻觉；行级越权与笛卡尔积防御在编译期天然实现。
