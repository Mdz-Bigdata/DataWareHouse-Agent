## 1. 本层定位与数据流

```
上游DSL(理解层输出)
     ↓
┌──────────────────────────────────────────────┐
│ 生成层 Generation                             │
│  ① DSL编译 / SQL生成                          │
│  ② 七层校验（防静默错误）★核心★              │
│  ③ 纠错重试                                   │
└──────────────────────────────────────────────┘
     ↓ 通过校验的 SQL
┌──────────────────────────────────────────────┐
│ 执行层 Execution                              │
│  ④ 成本预估 / 权限注入                        │
│  ⑤ 沙箱执行（只读/超时/限行）                 │
│  ⑥ 结果缓存                                   │
└──────────────────────────────────────────────┘
     ↓ 结果集
  结果解读 + 可视化推荐
```

**输入契约（理解层给的 DSL）：**
```json

  "dimensions": ["category"],
  "filters": [{"field": "region", "op": "=", "value": "East"}],

  "comparison": {"type": "yoy"},
  "order_by": [{"field": "gmv_yoy_growth", "dir": "desc"}],
  "limit": 3,
```

## 2. 语义 DSL → 物理 SQL 编译器

**关键原则：SQL 由编译器确定性生成，不是 LLM 直接吐。** 这样口径、字段、方言全部可控。

### 2.1 编译器结构

```python
class DSLCompiler:
    """把语义DSL编译成物理SQL。指标/维度定义来自语义层。"""

    def __init__(self, semantic_layer, dialect="ansi"):
        self.sl = semantic_layer      # 语义层：提供指标/维度的物理映射
        self.dialect = dialect
        self.render = DialectRenderer(dialect)   # 方言渲染器

    def compile(self, dsl: dict) -> str:
        # 1) 解析指标 → 拿到聚合表达式 + 所属事实表 + 默认过滤
        metrics = [self.sl.get_metric(m) for m in dsl["metrics"]]
        # 2) 解析维度 → 拿到分组字段
        dims = [self.sl.get_dimension(d) for d in dsl["dimensions"]]
        # 3) 确定主表 + 需要 JOIN 的维表
        base_table, joins = self._resolve_joins(metrics, dims, dsl["filters"])
        # 4) 构造 WHERE：用户过滤 + 时间 + 指标默认口径 + 权限
        where = self._build_where(dsl, metrics)
        # 5) 有对比 → 走对比模板（CTE 双时间窗）
        if dsl.get("comparison"):
            return self._compile_comparison(dsl, metrics, dims, base_table, joins, where)
        # 6) 普通聚合查询
        return self._compile_simple(dsl, metrics, dims, base_table, joins, where)

    def _build_where(self, dsl, metrics):
        conds = []
        # 指标自带的口径过滤（如 status='paid'）—— 用户无法绕过
        for m in metrics:
            if m.default_filter:
                conds.append(m.default_filter)
        # 用户显式过滤
        for f in dsl.get("filters", []):
            conds.append(self.render.condition(f["field"], f["op"], f["value"]))
        # 时间范围
        if dsl.get("time_range"):
            tf = self.sl.time_field(dsl["metrics"][0])
            conds.append(f"{tf} BETWEEN '{dsl['time_range']['start']}' "
                         f"AND '{dsl['time_range']['end']}'")
        # 行级权限（关键！由语义层根据当前用户注入）
        rls = self.sl.row_level_security(self.current_user)
        if rls:
            conds.append(rls)
        return " AND ".join(conds)
```

### 2.2 对比查询模板（同比/环比 —— 高频且易错，务必模板化）

```python
    def _compile_comparison(self, dsl, metrics, dims, base, joins, where):
        cur = dsl["time_range"]
        if dsl["comparison"]["type"] == "yoy":
            prev = shift_years(cur, -1)
        else:  # mom
            prev = shift_months(cur, -1)

        dim_cols = ", ".join(d.column for d in dims)
        metric_expr = metrics[0].agg_expr   # 如 SUM(amount)
        mname = metrics[0].name

        return f"""
WITH cur AS (
  SELECT {dim_cols}, {metric_expr} AS {mname}
  FROM {base} {joins}
  WHERE {where.replace(str(cur['start']), str(cur['start']))}
  GROUP BY {dim_cols}
),
prev AS (
  SELECT {dim_cols}, {metric_expr} AS {mname}
  FROM {base} {joins}
  WHERE {self._where_with_time(dsl, prev)}
  GROUP BY {dim_cols}
)
SELECT c.{dim_cols}, c.{mname},
       (c.{mname} - p.{mname}) / NULLIF(p.{mname}, 0) AS {mname}_growth
FROM cur c LEFT JOIN prev p USING ({dim_cols})
ORDER BY {mname}_growth {dsl['order_by'][0]['dir'].upper()}
LIMIT {dsl.get('limit', 100)}
""".strip()
```

> 把同比、环比、留存、漏斗、复购这类分析**模板化或语义层预置**，是防错的关键。让 LLM 现写窗口函数错误率极高。

### 2.3 方言渲染器（一套 DSL 适配多引擎）

```python
class DialectRenderer:
    """屏蔽 MySQL/ClickHouse/Doris/Presto 等方言差异"""

    DATE_TRUNC = {
        "mysql":      lambda unit, col: f"DATE_FORMAT({col}, {_mysql_fmt(unit)})",
        "clickhouse": lambda unit, col: f"toStartOf{unit.capitalize()}({col})",
        "presto":     lambda unit, col: f"DATE_TRUNC('{unit}', {col})",
    }
    LIMIT_SYNTAX = {
        "mysql": "LIMIT {n}", "clickhouse": "LIMIT {n}",
        "sqlserver": "TOP {n}",   # 位置不同，需特殊处理
    }

    def __init__(self, dialect):
        self.dialect = dialect

    def date_trunc(self, unit, col):
        return self.DATE_TRUNC[self.dialect](unit, col)

    def condition(self, field, op, value):
        # 统一转义，防注入
        if op == "IN":
            vals = ", ".join(self._quote(v) for v in value)
            return f"{field} IN ({vals})"
        return f"{field} {op} {self._quote(value)}"

    def _quote(self, v):
        if isinstance(v, str):
            return "'" + v.replace("'", "''") + "'"   # 转义单引号
        return str(v)
```

## 3. SQL 生成的两种模式

生成层有两种路径，按查询复杂度分流：

### 3.1 模式 A：DSL 编译（首选，占 80%+）

理解层输出规范 DSL → 编译器确定性生成 SQL。**口径可控、无幻觉、快。** 适用于聚合、排名、趋势、标准对比。

### 3.2 模式 B：LLM 直接生成 SQL（兜底，复杂长尾）

归因、复杂嵌套、DSL 表达不了的自由查询，退回让 LLM 生成 SQL——但**必须限定在语义层视图内**，且走全部七层校验。

```python
def generate_sql(dsl_or_query, mode, context):
    if mode == "compile":
        return compiler.compile(dsl_or_query)     # 模式A
    else:
        # 模式B：Prompt 里只给召回到的 Schema 子集 + few-shot 相似样例
        prompt = build_gen_prompt(
            query=dsl_or_query,
            schema=context["linked_schema"],       # 只给选中的表/字段
            few_shots=context["similar_examples"], # 检索到的相似 问题-SQL 对
            constraints="只能使用上述字段，禁止全表扫描，必须带时间过滤"
        )
        return llm.sql(prompt)
```

**模式 B 的 Prompt 关键约束：**
```
1. 只能使用【已提供的字段】，出现未提供字段视为错误
2. 必须包含时间过滤条件（防全表扫描）
3. 聚合查询的非聚合列必须出现在 GROUP BY
4. 禁止 SELECT *（明确列出字段）
5. 参考下方相似样例的写法
```

## 4. 七层校验：纵深防御静默错误

这是本层的**核心价值**。每一层拦一类错误，层层设防。

```
L1 语法校验      SQL能否解析      → SQLGlot/sqlparse 静态解析
L2 白名单校验    字段是否存在      → 比对语义层字段清单，杜绝幻觉
L3 语义回译      SQL在算什么       → LLM反译成自然语言，与原问题比对
L4 静态成本      会不会拖垮库      → EXPLAIN，拦全表扫描/笛卡尔积
L5 自洽性投票    多次生成是否一致   → 生成N条，结果一致才采信
L6 结果合理性    数值是否异常      → 占比>100%、同比>1000%触发复核
L7 透明可解释    让用户能复核      → 展示SQL+口径说明
```

### 4.1 L1 语法校验

```python
import sqlglot

def validate_syntax(sql, dialect):
    try:
        sqlglot.parse_one(sql, read=dialect)
        return {"ok": True}
    except Exception as e:
        return {"ok": False, "error": str(e), "layer": "L1_syntax"}
```

### 4.2 L2 字段白名单校验（防幻觉字段，最重要）

```python
def validate_whitelist(sql, dialect, semantic_layer):
    """抽出SQL引用的所有表和列，逐一比对语义层白名单"""
    parsed = sqlglot.parse_one(sql, read=dialect)
    used_tables = {t.name for t in parsed.find_all(sqlglot.exp.Table)}
    used_cols = {c.name for c in parsed.find_all(sqlglot.exp.Column)}

    allowed_tables = semantic_layer.allowed_tables(current_user)
    allowed_cols = semantic_layer.allowed_columns(current_user)

    bad_tables = used_tables - allowed_tables
    bad_cols = used_cols - allowed_cols
    if bad_tables or bad_cols:
        return {"ok": False, "layer": "L2_whitelist",
                "hallucinated_tables": list(bad_tables),
                "hallucinated_columns": list(bad_cols)}
    return {"ok": True}
```

### 4.3 L3 语义回译（抓业务逻辑错）

```python
BACKTRANSLATE_PROMPT = """用一句话描述这条SQL在计算什么，面向业务人员，不要技术术语。
SQL：{sql}
描述："""

CONSISTENCY_PROMPT = """判断【SQL的实际计算】是否满足【用户的原始意图】。
用户意图：{query}
SQL计算：{sql_desc}

重点检查：过滤条件、时间范围、聚合口径、分组维度是否都对上。
输出JSON：{{"consistent": true/false, "reason": "...", "confidence": 0-1}}"""

def validate_semantic(sql, original_query, llm):
    desc = llm.text(BACKTRANSLATE_PROMPT.format(sql=sql))
    check = llm.json(CONSISTENCY_PROMPT.format(query=original_query, sql_desc=desc))
    if not check["consistent"] or check["confidence"] < 0.7:
        return {"ok": False, "layer": "L3_semantic",
                "reason": check["reason"], "sql_desc": desc}
    return {"ok": True, "sql_desc": desc}
```

### 4.5 L5 自洽性投票（Self-Consistency，用于模式B）

```python
def validate_consistency(query, context, executor, n=3):
    """生成n条SQL，执行后比对结果，多数一致才采信"""
    sqls = [generate_sql(query, "llm", context) for _ in range(n)]
    results = []
    for s in sqls:
        if all(v["ok"] for v in [validate_syntax(s, ...), validate_whitelist(s, ...)]):
            results.append(executor.dry_run(s))   # LIMIT小样本试跑
    # 结果聚类，取多数
    if _majority_agree(results):
        return {"ok": True, "sql": _pick_majority(sqls, results)}
    return {"ok": False, "layer": "L5_consistency",
            "reason": "多次生成结果不一致，可能存在歧义", "action": "clarify"}
```

### 4.8 校验编排与纠错重试

```python
def validate_pipeline(sql, query, dsl, ctx):
    checks = [
        validate_syntax(sql, dsl["dialect"]),
        validate_whitelist(sql, dsl["dialect"], ctx["sl"]),
        validate_semantic(sql, query, ctx["llm"]),
        validate_cost(sql, ctx["executor"]),
    ]
    for c in checks:
        if not c["ok"]:
            return c   # 任一层失败即返回，带上失败层信息
    return {"ok": True}

def generate_with_retry(query, dsl, ctx, max_retry=2):
    sql = generate_sql(dsl, "compile", ctx)
    for attempt in range(max_retry + 1):
        result = validate_pipeline(sql, query, dsl, ctx)
        if result["ok"]:
            return {"sql": sql, "attempts": attempt + 1}
        # 把失败原因回喂给LLM纠错（针对模式B；模式A失败通常是DSL问题需澄清）
        if attempt < max_retry:
            sql = repair_sql(sql, result, ctx)   # 带错误信息重新生成
        else:
            return {"error": result, "action": _decide_fallback(result)}
```

## 5. 沙箱执行引擎

### 5.1 安全执行的护栏

```python
class SandboxExecutor:
    def __init__(self, conn_pool):
        self.pool = conn_pool   # 只读账号连接池

    def execute(self, sql, user, timeout=30, max_rows=10000):
        conn = self.pool.get_readonly(user)   # 只读，物理隔离写权限
        try:
            conn.set_statement_timeout(timeout * 1000)   # 超时熔断
            # 强制包一层 LIMIT，防止意外大结果集
            wrapped = self._enforce_limit(sql, max_rows)
            cursor = conn.execute(wrapped)
            rows = cursor.fetchmany(max_rows)
            if cursor.fetchone():   # 还有更多 → 提示被截断
                return {"data": rows, "truncated": True, "limit": max_rows}
            return {"data": rows, "truncated": False}
        except TimeoutError:
            return {"error": "查询超时，请缩小时间范围或增加过滤条件"}
        finally:
            self.pool.release(conn)

    def _enforce_limit(self, sql, max_rows):
        if "limit" not in sql.lower():
            return f"SELECT * FROM ({sql}) _t LIMIT {max_rows}"
        return sql
```

### 5.2 执行护栏清单

```
□ 只读账号        —— 从连接层杜绝写/删/DDL
□ 语句超时        —— statement_timeout，防慢查询拖垮库
□ 强制行数上限    —— 外层包 LIMIT
□ 成本预估门槛    —— 超阈值先二次确认（承接 L4）
□ 资源队列隔离    —— 问数走独立资源组，不影响生产报表
□ 并发限流        —— 单用户/全局 QPS 限制
□ 审计日志        —— 记录 user + query + sql + 耗时 + 行数
```

## 7. 缓存与性能

### 7.1 三级缓存

```python
def cached_query(dsl, user, executor):
    # L2 SQL缓存：相同DSL复用已验证SQL，跳过生成+校验
    sql_key = hash_dsl(dsl)
    sql = redis.get(f"sql:{sql_key}")
    if not sql:
        sql = generate_with_retry(..., dsl, ...)["sql"]
        redis.setex(f"sql:{sql_key}", 3600, sql)

    # L1 结果缓存：注意时效性 + 权限维度
    result_key = hash(sql + user.data_scope)   # 权限维度纳入key，防越权命中
    cached = redis.get(f"res:{result_key}")
    if cached and _fresh_enough(cached, dsl):
        return cached
    result = executor.execute(sql, user)
    redis.setex(f"res:{result_key}", _ttl_by_freshness(dsl), result)
    return result
```

> **缓存安全红线**：结果缓存 key 必须包含用户数据权限维度，否则 A 用户的缓存可能被 B 用户命中，造成数据越权泄露。

### 7.2 延迟优化

```
□ 简单查询走快速通道   —— 命中DSL模板直接编译，绕过LLM
□ 校验并行            —— L1/L2/L4 无依赖，可并发
□ 流式返回            —— 先返回SQL+"查询中"，结果异步补
□ 分级模型            —— 简单生成用小模型，复杂用强模型
```

## 8. 完整生成-执行 Pipeline

```python
class GenerationExecutionPipeline:
    def __init__(self, compiler, validator, executor, llm, semantic_layer):
        self.compiler = compiler
        self.validator = validator
        self.executor = executor
        self.llm = llm
        self.sl = semantic_layer

    def run(self, parsed: dict, user) -> dict:
        query = parsed["rewritten_query"]
        dsl = parsed["dsl"]
        dsl["dialect"] = self.sl.dialect_of(dsl["metrics"][0])

        # 1) 生成（模式A编译优先，复杂退模式B）
        mode = "compile" if _is_expressible_in_dsl(dsl) else "llm"
        gen = generate_with_retry(query, dsl, self._ctx(user), max_retry=2)
        if "error" in gen:
            return self._handle_failure(gen)   # 澄清/拒答/降级
        sql = gen["sql"]

        # 2) 权限注入已在编译期完成（RLS写进WHERE）

        # 3) 缓存 + 执行
        result = cached_query(dsl, user, self.executor)
        if "error" in result:
            return {"status": "error", "message": result["error"]}

        # 4) L6结果合理性
        rc = validate_result(result["data"], dsl)

        # 5) 解读 + 可视化 + 可解释交付
        insight = interpret(query, result, rc["warnings"], self.llm)
        chart = recommend_chart(dsl, result)
        explanation = build_explanation(sql, gen.get("sql_desc"),
                                        dsl["metrics"], dsl)

        return {
            "status": "success",
            "data": result["data"],
            "insight": insight,
            "chart_type": chart,
            "warnings": rc["warnings"],
            "explanation": explanation,      # 透明可解释（L7）
            "truncated": result.get("truncated", False),
        }

    def _handle_failure(self, gen):
        layer = gen["error"]["layer"]
        if layer == "L3_semantic":
            return {"status": "clarify", "reason": gen["error"]["reason"]}
        if layer == "L4_cost":
            return {"status": "confirm", "risks": gen["error"]["risks"]}
        if layer == "L2_whitelist":
            return {"status": "reject",
                    "message": "查询涉及不存在或无权限的字段"}
        return {"status": "clarify", "reason": "无法确定查询意图，请补充说明"}
```

## 附：本层核心原则速记

```
生成：  DSL编译为主(可控) + LLM生成兜底(限语义层内)，同比环比必模板化
校验：  七层纵深防御，L2防幻觉字段 / L3防业务逻辑错 是重中之重
执行：  只读+超时+限行+权限+审计，缓存key必含权限维度
交付：  永远展示SQL和口径，让用户能复核——透明是信任的前提
```

**一句话总结：**
> 本层的使命不是"生成一条能跑的 SQL"，而是"生成一条**能跑且业务正确、且被证明正确**的 SQL"。
> 宁可多一层校验拦下来去澄清，也绝不让静默错误流到用户面前。
